# 🌳 생명의 계통수 — 온라인 베타

GitHub Pages에서 실행되고, Firebase Realtime Database로 플레이어끼리 상태를 주고받는 2~6인 온라인 보드게임입니다.
서버 코드가 없어서 정적 파일만 올리면 됩니다.

---

## 1. Firebase 설정 (처음 한 번, 약 5분)

1. https://console.firebase.google.com 에서 **프로젝트 추가**를 누릅니다. 애널리틱스는 꺼도 됩니다.
2. 왼쪽 메뉴 **빌드 → Realtime Database → 데이터베이스 만들기**를 누릅니다.
   - 위치는 `asia-southeast1 (싱가포르)`를 추천합니다.
   - 처음에는 **테스트 모드로 시작**을 고릅니다.
3. **규칙** 탭에 이 폴더의 `database.rules.json` 내용을 붙여넣고 **게시**합니다.
   (테스트 모드 규칙은 30일 뒤 막히므로 꼭 바꿔 주세요.)
4. **프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → 웹 앱(`</>`) 추가**를 누릅니다. 이름은 아무거나 넣고, 호스팅 체크는 하지 않습니다.
5. 화면에 나오는 `firebaseConfig = { ... }` 값을 복사해서 **`js/firebase-config.js`** 에 붙여넣습니다.
   `databaseURL` 줄이 꼭 있어야 합니다. 없으면 2번 단계를 먼저 했는지 확인하세요.

> apiKey는 공개돼도 괜찮은 값입니다(웹 앱 식별용). 대신 누구나 `rooms/` 아래를 읽고 쓸 수 있으므로 **베타테스트용**으로만 쓰세요.

## 2. GitHub Pages에 올리기

1. GitHub에서 새 저장소를 만듭니다 (예: `tree-of-life`). Public이어야 무료로 Pages를 쓸 수 있습니다.
2. **Add file → Upload files**를 누르고, 이 폴더 안의 **내용물 전부**(`index.html`, `css/`, `js/`, `img/`, `.nojekyll` 등)를 끌어다 놓고 커밋합니다.
   또는 터미널에서:
   ```bash
   git remote add origin https://github.com/<아이디>/tree-of-life.git
   git push -u origin main
   ```
3. 저장소 **Settings → Pages → Build and deployment**에서 Source를 `Deploy from a branch`, Branch를 `main` / `(root)`로 정하고 저장합니다.
4. 1~2분 뒤 `https://<아이디>.github.io/tree-of-life/` 에서 열립니다.

## 3. 플레이 방법

- 닉네임을 넣고 **새 방 만들기**를 누르면 4글자 방 코드와 초대 링크가 나옵니다. 친구는 링크로 들어오거나 코드를 입력해 **참가**합니다.
- 2명 이상 모이면 방장이 **게임 시작**을 누릅니다. 플레이어 순서는 무작위입니다.
- 새로고침하거나 창을 닫았다가 같은 브라우저로 같은 링크에 들어오면 내 자리로 돌아옵니다(브라우저 저장소에 ID가 저장됨).
- 이미 시작한 방에 새 사람이 들어오면 관전자가 됩니다.
- **로컬 테스트**: Firebase 없이 한 화면에서 여러 명이 번갈아 하는 모드입니다. 규칙을 확인할 때 쓰세요. "이어하기"로 이전 판을 복구합니다.

조작:
- **구매**: 시장 카드 클릭 → 구매
- **사용**: 아래 손패 카드 클릭 → 사용 (타일을 골라야 하면 지도가 파랗게 표시됨)
- **진화**: 내 보드의 진화 트랙 노드 클릭 → 낼 DNA/단백질 수 선택
- **연구 / 특성 발현**: 해당 트랙의 다음 칸 클릭
- **턴 종료**: 하단 오른쪽 버튼 (제한 효소·조직 배양이 있으면 그때 선택)
- 공격을 받으면 방어 카드(세포막·항체)를 쓸지 묻는 창이 자동으로 뜹니다.

## 4. 설명서에서 애매해서 이렇게 정한 것 (베타 피드백 대상)

| 항목 | 이 구현의 처리 |
|---|---|
| 연구·특성 발현의 "RNA n" 비용 | 구매와 같은 **화폐 값**으로 계산 (RNA 1장 = 2, PCR이면 1장 = 4) |
| "단백질/RNA를 얻는다·가져온다" | 공용 공급에서 **손패로** 가져옴 (공급이 바닥나면 못 받음) |
| 구매·연구 지불 | 손패의 RNA를 최소 장수로 자동 지불, 거스름돈 없음 |
| 카드의 지형 아이콘 | "강화:" 문구가 있는 카드만 효과가 바뀜. 문구가 없으면(신경계·포식자 등) 표시만 |
| 진화 노드 개방 시 진열 | 그 계통의 카드 종류 중 하나를 **개방한 사람이 고름** |
| 진열대에서 치운 더미 | 남은 카드는 상자로 돌아가고 나중에 다시 진열될 수 있음 |
| 계통 카드 구매 조건 | 그 계통 노드를 **내가** 개방해야 함 (연구 3단계면 무시) |
| 수평적 유전자 전달 | 가져온 카드는 버림더미로. ★ 카드는 최초 개방자/연구 3단계만 |
| 극한 환경 적응 | 고른 사막·수생태계 타일의 K를 먼저 +1 하고 그 타일에 2개 배치 |
| 근육과 골격 / 섬모와 편모 이동 | 인접 타일로만 (비행 특성이면 무시) |
| 다세포화 "산출량 +1" | 자원 생산 효과의 첫 번째 자원에 +1 |
| 라운드당 1회 방어(세포벽·내생 포자·보호색·의태·항상성) | 조건이 되면 **자동 적용** |
| 포자·재생 재배치 위치 | 자기 개체가 가장 많은 놓을 수 있는 타일에 **자동 배치** |
| 세력권 | 새 배치뿐 아니라 이동해 들어오는 것도 막음 |
| 지도에 내 개체가 0개일 때 | 아무 타일에나 배치 가능 (막힘 방지) |
| 능력 슬롯 | 노드마다 +1, 세포내 공생 +1, 최대 6 |
| 공급 수량 | `js/data.js`의 `SUPPLY` (2인 기준). 인원이 늘면 자원·유해 돌연변이가 자동으로 늘어남 (`engine.js`의 `scaledSupply`) |

> 베타 편의상 다른 사람의 손패가 데이터베이스에 그대로 저장됩니다. 개발자 도구로 볼 수 있으니 친한 사람끼리만 테스트하세요.

## 5. 파일 구조

```
index.html             진입점
css/style.css          화면 스타일
js/data.js             카드·노드·특성·업적·연구 데이터 (밸런스 수치는 여기서 수정)
js/engine.js           규칙 엔진 (모든 규칙 판정과 점수 계산)
js/net.js              Firebase / 로컬 모드 통신
js/app.js              화면과 입력 처리
js/firebase-config.js  ← 내 Firebase 설정을 붙여넣는 곳
img/                   카드·업적 이미지
database.rules.json    Realtime Database 보안 규칙
```

데이터 구조: `rooms/{방코드}/info`, `players`, `chat`, `state`. `state`는 게임 전체 상태를 JSON 문자열 하나로 저장하고, 행동할 때마다 트랜잭션으로 갱신합니다. 그래서 두 사람이 동시에 눌러도 상태가 꼬이지 않습니다.
